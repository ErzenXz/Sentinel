# Sentinel v0.10.0 — recheck findings and reduce feed-refresh overhead

Select a retained finding and choose **Scan file again** to read its current file with the current threat list and chosen scan speed. Contained findings recheck the whole archive. The fresh scan replaces the results view and saves a report in Scan history; canceled scans keep their completed results. No file is removed automatically.

Signed-feed refreshes no longer copy the entire received envelope into a second array or load a second whole-file cache array. Base64 payload/signature bytes decode directly from UTF-8, and validated indicator keys become the compacted lookup index. Declared response sizes are checked before allocation; streamed downloads still enforce the 24 MiB limit. Cache comparisons use a cleared pooled buffer and freshly validated local paths. Identical signed envelopes are reverified and fully compared, then retained without rewriting or flushing cache and sequence files. Changed same-sequence content, rollback, expired feeds, malformed encodings and cancellation remain rejected with committed state retained. The active catalog retains its verified payload digest, so deleting its cache cannot authorize different content under the same sequence. Identical bytes can rebuild a missing cache while that catalog is active; after restart, a known sequence with missing cache requires a newer signed publication and keeps rollback state intact.

The new benchmark includes 10,000 signed harmless indicators and unchanged-feed refreshes, with signing/fixture setup outside the measured iterations. Paired baseline/candidate runs use the same harness and output directory. Managed allocations fall 52.0% for this refresh workload on both Windows x64 and Mac ARM64; elapsed-time changes vary across Windows repeats. This is not a 52% reduction in total app RAM. [Performance results and limits](PERFORMANCE.md) distinguish managed allocations from working set and ordinary product memory.

Native Windows verification passes 112 assertions and now tests selected-file rescans, current-byte coverage and saved history, in addition to prior page/selection/scan/retention/shutdown checks. The diagnostic resource workflow compares fresh windows, bitmap-capture bursts, hidden windows and post-verification runtime threads. A separate run disables tiered compilation only to investigate warmup; production runtime defaults remain enabled. [Native verification](NATIVE-UI-VERIFICATION.md) includes actual WPF fixture screenshots viewable from macOS.

The release requires 131 core tests, 13 server tests, native x64 WPF verification, both Windows x64/ARM64 builds and package checks. This is an unsigned development preview. Native ARM64 execution, hardware DPI/Narrator/OS protection acceptance, quiet-hardware startup/idle/throughput, signing/driver/service work and independent detection evaluation remain open. Keep Defender enabled.
