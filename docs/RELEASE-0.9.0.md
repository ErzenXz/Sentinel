# Sentinel v0.9.0 — release scanner pages and verify the native interface

Repeated scanner navigation previously retained each `ListCollectionView` through its subscription to the window's finding collection. Discarded pages now clear the table source, count binding and filter, detach the view and stop their monitoring status timer. Navigation and shutdown release the page. The Windows fixture regression changes from twelve retained views after twelve visits to zero; managed heap no longer grows in that sequence. This is a specific leak fix, not a percentage reduction in ordinary process memory.

Tables require explicit selection. WPF previously synchronized the first scanner row to its collection's current item before the evidence handler was attached, leaving the selected full-evidence inspector empty. Path, reason and SHA-256 now appear when selecting a finding; selection-dependent actions begin disabled. Text inherits its button's brush, fixing dark string labels on green primary buttons and correctly coloring quiet, destructive and disabled actions.

A new Windows x64 CI job exercises the production WPF control tree with read-only status fixtures and an isolated temporary profile. It renders every page at 1200 × 820 and 960 × 680, both inspector arrangements, expanded settings/monitoring, selected evidence, busy startup and a paused scan. Binding/layout errors, action eligibility, search, scan pause/resume/cancel/subsequent execution, collection-view retention and shutdown are checked. Native fixture PNGs and JSON diagnostics are uploaded separately from product archives. Tagged publication now requires this job and both Windows x64/ARM64 build/test/package jobs.

The existing 125 core and 13 server tests remain release gates. No engine rules, user intelligence, firewall policies or model integrations are changed. No paid inference, real malware or user credentials are used by the native fixture. [Native verification](NATIVE-UI-VERIFICATION.md) describes methods and limits; [performance](PERFORMANCE.md) distinguishes retention from working set and records the fixture's high software-rendered CPU sample without claiming an idle CPU improvement.

This remains an unsigned development preview. Windows ARM64 native execution, actual OS high contrast, hardware DPI/text scaling, Narrator, tray/OS enforcement, quiet-hardware performance and independent detection evaluation remain open acceptance gates. Keep Defender enabled.
