# Sentinel v0.8.0 — stronger monitoring with bounded background work

Starting or resuming a watched folder now scans existing files in Low impact mode while incoming changes stay queued. Directory-name notifications cover populated folders moved/renamed into the root. Missed watcher events, full queues, verified-feed updates and Recheck watched folder coalesce into one recovery request. One worker serializes recovery and settled file changes; recoveries wait at least 30 seconds after the previous one finishes and use a five-minute cooperative scan budget. Timeout/limits/excluded storage remain incomplete, completed findings stay available, and ordinary event scanning continues after a recovery deadline. Permanent watcher failures mark monitoring stopped.

A bounded 512-item deduplicated inbox replaces per-finding/per-problem UI callbacks. The native session drains at most 128 findings every 200 ms; large worker deliveries yield between batches. Exact detections take priority, omission counts are visible, and the 2,000-row display cannot evict exact detections for review findings. Live monitoring details show changed-file checks, queues, missed events and last recovery coverage. Notifications contain batched counts only. Stopping monitoring drains findings already delivered to the inbox; stop/shutdown/page unload release their timers.

Local verification: 125 core tests, 13 server tests and real server/CLI interoperability pass; WPF Release compilation has zero warnings/errors. New monitoring tests exercise real filesystem changes, moved folders, overflow, cancellation, rewrites, recovery cooldown/timeouts, storage exclusions and a 160,000-addition concurrent inbox burst using benign signed-hash fixtures. The same-harness Mac regression check shows essentially unchanged ordinary scan allocations (17,488,800 vs 17,488,816 bytes for the folder workload). Active monitoring and Windows working set are not benchmarked; no new speed/RAM-saving percentage is claimed.

GitHub Actions gates publication on both Windows x64/ARM64 build/test/package jobs and checked architecture, runtime, versions, documentation, ZIP integrity and checksums. Source and the self-hostable server are included. No installer, driver, privileged service, automatic deletion or AI background loop is added.

This remains an unsigned development preview. Keep Defender enabled. Native Windows monitoring/GUI/accessibility/performance and full antivirus certification gates remain open; follow the Windows acceptance checklist before broader distribution.
