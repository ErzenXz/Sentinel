# Sentinel v0.11.0 — more archive coverage, less repeated work

Sentinel now inspects regular V7/ustar TAR entries, GZIP payloads and TGZ, including mixed nested ZIP/TAR/GZIP trees. It reads archive contents without extracting files and uses shared count, size, expansion, ratio and nesting budgets. Contained findings retain their outer container identity; quarantine confirmation rechecks current bytes and current intelligence before removing the complete container. Corrupt/truncated streams, unsafe names, TAR links/special files, PAX/GNU/sparse extensions and other unsupported formats remain visible as incomplete coverage. Nested containers over the 16 MiB seekable-copy budget remain incomplete.

ZIP preflight reuses bounded scratch buffers and compact header records. Entries at the nesting limit retain their full hash check without an unused archive copy. Manual and automatic signed-feed checks only queue watched-folder recovery when the effective exact-hash keys change, including revocations. Renewed sequence/expiry, labels and provenance are still verified and committed, with no unnecessary folder reread. Initial coverage, file changes, missed events and explicit rechecks continue as before.

The paired benchmark compares v0.10 with v0.11 using identical benign fixture bytes and coverage assertions. [Performance measurements](PERFORMANCE.md) distinguish temporary managed allocations from peak/retained heap, working set and whole-app costs. Windows x64 managed allocations fall 25.0% for 1,024 small ZIP entries and 98.6% for an 8 MiB nested ZIP at the configured depth limit, with full hash checks retained. No overall RAM, idle CPU or comparative antivirus claim is made.

Verification covers new formats, mixed trees, checksums, truncation/trailing bytes, optional metadata, unsafe names, shared budgets, changed/revoked quarantine confirmation and hash-set-driven recovery. A deterministic 600-mutation archive corpus supplements targeted regressions; it is not an independent parser audit or coverage-guided fuzzing. Actual Node-created TAR/GZIP/TGZ fixtures pass through the low-impact CLI and signed server feed. Native Windows UI verification passes 116 assertions and adds contained TGZ review, action eligibility, saved history and a build-derived version label. All 143 core tests and 13 server tests pass. Release publication requires both Windows architecture builds, core/server tests, native x64 WPF checks and strict-compression package validation.

This is an unsigned development preview. Native ARM64 execution, real Windows protection enforcement/UAC/DPAPI, hardware accessibility, quiet-hardware performance, installer/service/driver/signing work and independent detection evaluation remain open. Keep Defender enabled.
