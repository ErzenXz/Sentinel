# Security boundaries

Sentinel v0.9 has an independent exact-hash scanner and recoverable quarantine, alongside Microsoft Defender/Windows Firewall controls. It has no signed on-access minifilter, protected anti-malware service, tamper resistance, broad archive-format coverage, behavioral ransomware engine, packet-inspection engine, or AV Security Center registration. It is not certified as an antivirus replacement.

- ZIP contents are streamed without extraction, with central/local metadata preflight, CRC checks and bounded entry/depth/expansion budgets. Unsupported/encrypted contents remain incomplete. Whole-container quarantine needs explicit confirmation and revalidation; entry names are never filesystem destinations.
- Scan files locally against bundled/verified hashes. New/modified malware may not match. Review-only patterns never authorize quarantine. Missing/read-failed files are not safe verdicts.
- Online feed trust comes from an explicitly pinned operator public key; TLS alone cannot authorize a new signer. Limits, signature, sequence and expiry are checked. A compromised signing operator can publish wrong indicators, so file remediation stays user-reviewed.
- The self-hosted server serves signed catalogs only. It never receives local file contents or per-file hashes. ESET fetching reads published text lists, while the optional MalwareBazaar connector requests metadata only. Operator tokens/signing keys stay on the server.
- Quarantine uses authenticated encrypted chunks and Windows user-scoped DPAPI. The source is locked/rehashed and backed up before removal by handle. Restore verifies identity/order/length/hash and cannot overwrite existing files. User/admin malware can tamper with this user-mode store; see PROTECTION-ENGINE.md for crash and recovery limits.
- Folder monitoring is a bounded, best-effort user-mode observer after filesystem changes. It is not a pre-execution block. Overflow is visible. Own storage is excluded before reads; rewrites during scans are requeued. A bounded initial scan checks existing files; directory moves, overflow and verified-feed updates queue recovery. Rechecks share the worker and have a five-minute cooperative deadline and a 30-second cooldown. Partial coverage and dropped display findings remain explicit; manual saved scans are required for a full report. Permanent watcher errors stop monitoring rather than claim continued coverage. Daily tasks use a limited interactive user account and never remove files.
- Defender/Firewall are OS enforcement boundaries. Their unavailable state, disabled services, passive mode, policies, and partial errors stay visible. Whole-app elevation is user-requested through UAC, and AI/personal-file remediation reject elevated sessions. A narrow signed write broker remains future work.
- PowerShell uses the absolute Windows system executable, no profile, fixed scripts, and JSON/base64 parameter data. File paths/rule names never become command fragments. Firewall deletion checks Sentinel ownership.
- A file signature identifies a publisher, not safe behavior. AI replies and unsigned binaries do not trigger automatic blocking/deletion.
- API keys use DPAPI. The bounded activity log stores generic action names/outcomes; quarantine indexes and local scan reports store paths locally. The last 30 scan reports are retained, including completed findings from canceled runs. Reports are validated on import and detections are rechecked before remediation. These are not tamper-proof audits.
- AI gets only the entered question and optionally the displayed sanitized snapshot. File contents, raw local hashes, and full process inventories are not sent by the app. Selected error findings omit local error strings; review the preview before sharing. AI remains advisory. Codex is an experimental separately authenticated runtime with disabled native tooling and policy confirmation.

No public security inbox/issue tracker is configured yet. Before distribution establish private vulnerability reporting, signed releases, a narrow broker, secure updates, and a Windows review. Do not include real credentials or private security data in public bug reports.

- Tray mode, notifications, folder resume and recurring signed-feed downloads are explicit user preferences. They install no service or login startup task. Exit cancels work and awaits completion; a hidden tray window is still a running process. Native notifications disclose counts only, may be suppressed by Windows and never authorize remediation.
- Model listing uses bounded metadata-only GET requests. It transmits provider authentication to your configured endpoint, with redirects disabled, but sends no security evidence or inference prompt. Model IDs are untrusted text and do not prove chat compatibility.
- One interactive instance per profile/session reduces conflicting user-mode writes. Its window message only restores the window. This is not authenticated security IPC or a tamper-resistance boundary. Feed trust reset and updates share a gate; private local storage remains user-writable.

- Fast firewall review observes bounded TCP/identity/profile metadata on demand. It does not attribute connections to matching firewall rules, inspect packets/UDP, establish listener reachability or identify malware from addresses. Process identity is checked again by PID, start time and executable path before selected publisher inspection/blocking. A firewall block remains a confirmed exact-path OS rule and cannot automatically close a listener.
- Jev is a separate typed-decision HTTP adapter. Only whitelisted categories/counts cross its boundary after a fresh-snapshot and explicit sharing check in the app. Raw executable names/paths, IPs, PIDs and publisher/error strings never enter that payload. Model confidence is untrusted statistical advice, not a permission or safety guarantee. It cannot lower deterministic warnings, trigger changes or bypass UAC. Unavailable/uncertain decisions require manual review.
- The Jev connection settings and API key are encrypted together in one DPAPI file, staged through a unique create-new file. Provider changes clear the UI key. The memory-only review cache keys include settings, hashed credential identity and exact sanitized evidence; entries expire after two minutes and are capped at 128. Failed/canceled reviews are not cached. No automatic retries or continuous AI loop is installed.
