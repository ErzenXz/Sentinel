# Windows acceptance checks

These checks remain pending until run on Windows. Portable unit tests and cross-compilation do not substitute for them. Use a disposable Windows 11 VM for firewall modifications.

1. Extract a portable build and launch as a standard user. Verify Home against Windows Security and `Get-MpComputerStatus`. Check all three firewall profiles against `Get-NetFirewallProfile`.
2. Test disabled protection and failed API reads in a VM. Ensure Home shows attention/unavailable rather than green. Restore Windows protection afterward.
3. Run a quick scan and signature update. A successful request should refresh actual status. Test denied rights/policy. Full scan cancellation must say the app stopped waiting and that Defender may continue.
4. Inspect applications; compare an unsigned test app and a signed Windows binary. Check long publisher/path text, protected-process omission, filtering, selection, and scan targeting.
5. As administrator, block a disposable test executable. Verify the enabled outbound block's program/group/profile in Windows Firewall and test connectivity. Remove it through Sentinel and verify restoration. Confirm unrelated rules are never removed. Test domain policy overriding local rules.
6. Review TCP connections against `Get-NetTCPConnection`. Test empty/error results and a process that exits between snapshots.
7. Configure a local model first. Ask with snapshot unchecked and checked; inspect local server requests to confirm exactly what was sent. Test missing model, 401, malformed JSON, oversize response, timeout, and cancel. No security setting should change from an AI reply.
8. Save an API key. Confirm settings JSON and activity JSONL do not contain it; verify the DPAPI file cannot decrypt as another user. Test corrupt/missing key recovery and endpoint changes.
9. Confirm AI requests are rejected in elevated sessions. For experimental Codex, test dedicated login, no inherited MCP/skills, initialization/version errors, read-only policy and disabled tools, rejected tool requests, usage exhaustion, and process shutdown on cancellation.
10. Verify keyboard navigation, screen reader names, high DPI (100–200%), long content, resizing, and high contrast. Check memory and CPU after idle, inspection, scans, and repeated AI reviews. Report process costs separately from Defender and local model costs.

Do not use live malware for development. Do not claim detection coverage from a harmless test file or signature-state indicator.

## v0.2 independent-engine acceptance

11. Scan a harmless exact-hash fixture using the server demo feed and a no-match file using the bundled ESET catalog. Verify known/review/no-match/error counts. Confirm no network requests occur during scanning. Test size/depth/entry/finding limits and cancellation.
12. Test signed updates from a local/HTTPS server, wrong public key, private-key import rejection, altered body/signature, expired feed, future timestamps, rollback, same-sequence changed contents, and power-loss/restart around feed commits. Verify the last trusted list is retained or a visible recovery error is shown.
13. Quarantine only a harmless custom-hash fixture with a normal user account. Verify exact content restoration and original removal through the locked handle. Test changed/locked source, missing delete rights, DPAPI failure, cancellation, corrupt/truncated/swapped vault data, full disk, and crash recovery. Do not disable Defender to write the standard AV test marker; unit tests inspect that marker in memory.
14. Start monitoring a disposable folder. Test burst writes, renamed files, file locks, queue overflow, junctions, closing the app, and concurrent feed refresh. Events can be missed; verify the UI calls for a manual rescan.
15. Schedule a daily scan with the bundled Scanner executable. Verify the current user's limited interactive token, local time, quoted paths (including spaces/trailing slash), battery deferral, timeout, report/exit codes, and task removal. Moving/deleting the portable folder should produce an understandable failed task.
16. Load a scheduled report, including one with stale/revoked detections. Quarantine must rescan using the current catalog before removal. Test malformed/oversized reports.
17. Confirm AI preview shows only engine counts/feed state and selected evidence/extension. Error text with private paths must be omitted. The entered question can contain anything the user types, so retain explicit per-question snapshot consent.

The Node server and cross-language signed-feed flow were tested locally. Docker/reverse-proxy deployment remains unverified here. No malware binaries were used.

## v0.3 acceptance additions

17. Scan disposable stored/deflated ZIPs and nested ZIPs containing only harmless fixtures. Verify entry/outer hashes, separate counters, CRC failures, malformed/ZIP64/encrypted/unsupported entries, traversal/link names, budget exhaustion, and no extracted files on disk. Fuzz the preflight and compare against independent ZIP implementations.
18. Confirm a contained exact detection asks to quarantine the **whole archive**. Change unrelated archive content after detection and verify removal is refused; revoke the entry's indicator and verify removal is refused. Restore the whole archive byte-for-byte. Keep Defender enabled throughout.
19. Cancel a large folder/archive scan after completed detections. Verify partial evidence, canceled/incomplete status, report history across restarts, 30-report retention, import/export, v0.2 report compatibility, malformed/oversized data, blocked/symlinked report destinations, and failures during report saves. A scan canceled before starting may have no report.
20. Rewrite a monitored file while it is being scanned, burst multiple settled files, rename populated directories, exclude Sentinel storage, overload the queue and close/reopen the app. Verify rescan requirements, monitor generations, counters and clean stop behavior.
21. Schedule without a server and verify bundled fallback. Inspect next/last run and native result codes, offline cached-feed operation, missing/moved portable executables, Task Scheduler policies and limited user execution.
22. On a self-hosted server, inspect `/healthz` for publication age, source counts, failed/last-successful refresh state, expired feeds and interrupted publications. Verify failures do not alter the signed corpus or expose credentials/upstream error text. A publication timestamp is not a corpus-completeness claim.

23. Start with a fresh profile: tray, notifications, resume and auto-feed checking must all be disabled. Enable each separately; save/restart, disable again and inspect local preferences. Test missing, corrupt, oversized and linked preferences and inaccessible resume folders. Elevated sessions must skip personal monitoring/tray operations.
24. Close to tray during a scan; verify the scan continues, the monitor remains active and Open/notification click restores the window. Reopen the same executable, then test a second extracted copy, a hung first process and UAC restart handoff. Choose Exit during scanning, feed downloads and quarantine/restore; verify completion/cancellation settles without a second writer or stale icon.
25. Burst harmless feed detections, verify count-only notifications and the 30-second flush/throttle; disable notifications and test Focus Assist/policy suppression. Local findings must remain reviewable without notification delivery.
26. Enable automatic feeds: immediate check, one check every six hours after completion, no overlap with manual updates, cancellation on exit/trust changes. Disconnect or serve invalid/expired/rolled-back feeds; inspect retained cache, failed status and last success. Reset trust while an update is waiting/running.
27. Search and filter findings/history; confirm counts/evidence in exported reports are unchanged. Test keyboard navigation, scaling, narrow windows, high-contrast theme switches (including between two contrast palettes), selected rows, disabled controls and tray menus.
28. Discover models using local fixtures and a real opt-in provider: listing must make GET requests with no prompt/security body, preserve manual IDs, report truncation and fail generically on provider errors. Test missing keys, blocked redirects, malformed/oversized responses and cancellation. A listed model may not support inference.

29. Refresh the local firewall review with empty/large TCP tables, IPv4/IPv6/mapped loopback, private/link-local/shared addresses, wildcard/listening binds, protected/exited processes, disabled/missing/duplicate profiles and failed cmdlets. Confirm the 1,000-record bound, explicit availability states and global warnings even when no connections are returned. No background polling, DNS lookup or inventory-wide signatures should run.
30. Select an app, inspect its publisher and restart/replace the process between capture and inspection. Test PID reuse, changed start time, changed path and inaccessible identities. Block confirmation must identify the exact path and outbound-only effect; verify UAC, policy override, native rule persistence/removal and that a block is not presented as closing inbound listeners.
31. Configure both Jev providers with user-owned test accounts. Review outbound payloads: fixed categories/counts only, no paths/names/PIDs/IPs/publishers/error strings, no tools. Verify fresh-snapshot/share gating, key clearing on provider changes, standard-user restriction and DPAPI portability failure across users. Use test providers for quota/timeout/redirect/malformed/oversized responses; failures cannot lower local warnings or perform an action.
32. Test Jev cache expiry, repeated evidence, configuration/key changes, cancellation while queued/running, app exit and a view/selection change during a request. Request latency and cache use should be visible. Benchmark real Windows capture/policy/signature/UI latency and idle behavior separately on x64/ARM64. Evaluate priority false positives/false negatives on labeled representative examples before relying on Jev advice.

## v0.6 UI acceptance additions

33. Test every page at 960 × 680 and 1200 × 820, at 100%, 150%, 200% DPI and 150% Windows text size. Cards/action rows must wrap and scroll without horizontal clipping. Settings must stay accessible at the bottom of the rail. Compare normal, both high-contrast palettes and live theme changes, including selected grid text, focused inputs and disabled primary buttons.
34. Navigate only with a keyboard: Tab/Shift+Tab; Up/Down/Home/End on rail buttons and Enter/Space to open; F6/Shift+F6 between rail (including pinned Settings) and page content; Ctrl+O for file, Ctrl+Shift+O for folder, and Escape/Stop waiting during an operation. Test shortcuts while busy and while a dialog is open. Confirm focus after Home actions, Explain with AI, and direct provider/Jev/server settings links.
35. Use Narrator to review heading, navigation labels, named provider/key/model fields, selected evidence and AI previews. Repeated validation messages and coalesced progress/completion should be announced without a flood. This remains a manual acceptance check, not a proven accessibility claim.
36. Verify empty findings/history/quarantine/application/network views, no-result filters and read failures. Failure states must not imply an empty safe collection. Selection-specific actions must be disabled until eligible; quarantine only exact detections in standard-user sessions, restore only in standard-user sessions, and Jev only with fresh selected evidence and explicit sharing consent.
37. Cancel harmless scans with no findings, with partial findings, and with archive/coverage limits. Verify the global indeterminate indicator and cancellation remain reachable while page controls are disabled, navigation still works, saved totals stay distinct from in-progress counts, incomplete/canceled summaries stay visible, and final UI progress agrees with saved reports. Stress 50,000 harmless entries and confirm worker progress cannot enqueue one dispatcher callback per file.
38. Open and return to advanced sections; expansion is remembered in memory for the current session. Home threat-list links and provider/Jev setup links should expand the relevant Settings section, scroll to its header and move keyboard focus there. Enabling snapshot sharing reveals the exact preview; selection changes reset Jev consent. None of these UI changes may trigger an unrequested model call, firewall write, restore or quarantine.

Verify result labels and numeric headers fit, long evidence remains selectable, Home's compact rows grow for text scaling, and scan timing below results remains reachable by keyboard and direct disclosure links.

## v0.7 scan controls and resource additions

41. On x64 and ARM64, scan benign wide/deep folders and ZIPs in both modes. Check pause/resume, rapid toggles, page navigation, Ctrl+O while busy, Tab to status controls, Narrator labels, high contrast and the 960 × 680 layout. An in-flight read may finish before pause; paused progress must not imply completion. Cancel and Exit while paused must settle, close handles, save partial findings and restore controls for the next scan.
42. Test read/reparse/rename changes during streaming traversal, hidden/system files, OneDrive placeholders, junctions, exact entry bounds, long paths and depth limits. Compare complete hashes/verdicts across modes. Low-impact scan mode does not pause the monitor or Defender.
43. Measure startup/idle working set and CPU, wide/large/ZIP scan throughput, peak heap/working set, first finding latency, report/history load, low-impact desktop responsiveness and paused resource use on x64/ARM64, with Defender enabled. Run the published benchmark on a quiet host and record raw results; do not infer Windows savings from Mac managed-allocation samples.
44. Import older reports, export/cancel large reports, exceed the 16 MiB bound, and verify existing destinations/staging recovery. Confirm mode and directory-level metadata survive export/import while remediation still rescans against current intelligence.

## v0.8 monitoring coverage and resource additions

45. Start and resume monitoring with pre-existing harmless signed-hash fixtures, ZIP-contained fixtures and a sibling folder whose name shares the excluded-storage prefix. Verify initial counts, storage exclusion before reads, incomplete coverage labels and newly written files during that initial scan. Move/rename a populated directory into the watched root and confirm its files are covered by a queued recovery.
46. Stress native watcher buffer/file queue overflow with harmless changes. Verify at most one recovery pending, no simultaneous event/recovery scanner, 30-second cooldown, ordinary changed-file detection during that cooldown, and another recovery for changes missed during an active scan. A permanent watcher failure must say monitoring stopped; changing/disconnecting/removing the root must never leave an apparent successful ongoing watch.
47. On a large tree, check the five-minute cooperative recovery budget, retained completed findings, explicit timeout/count/depth/archive/display limits, and continued event scanning afterward. Recheck manually and after a successful signed-feed update; failures must retain prior verified intelligence and cannot silently report full coverage. Stop/Exit while recovering or waiting for cooldown must release directory/file handles and settle without requiring Resume. Attempt Start immediately after Stop and Exit during a pending stop; the new monitor must wait, shutdown must await the same stop task, and late old messages must not mark a new monitor stopped.
48. Produce a large batch of harmless exact/review findings, block the UI temporarily and inspect pending UI operations/managed heap. Inbox and display caps, deduplication, exact-detection priority and omitted counts must hold. Restore UI responsiveness, stop monitoring and verify already delivered inbox findings remain visible. Notifications must contain batched counts only. Page navigation/unloading, tray hiding/reopening and shutdown must not leak timers or old-monitor callbacks.
49. Verify Recheck/Stop actions, live counts, coverage warnings, long paths, high contrast, Narrator and keyboard focus at 960 × 680 and with increased text scaling on x64/ARM64. Measure idle monitoring CPU/memory, initial scan overhead, burst recovery responsiveness and total working set with Defender enabled. Mac core allocation parity does not prove these native results.
